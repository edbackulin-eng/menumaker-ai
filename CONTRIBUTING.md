# Contributing

## Формат комітів

Проєкт дотримується [Conventional Commits](https://www.conventionalcommits.org/):

```
<type>(<scope>): <короткий опис>
```

Типи:

- `feat` — нова функціональність
- `fix` — виправлення бага
- `chore` — рутинні зміни (залежності, конфігурація, без впливу на код продукту)
- `docs` — зміни лише в документації
- `refactor` — зміна коду без зміни поведінки
- `test` — додавання/зміна тестів
- `style` — форматування, без зміни логіки

Приклади:

```
feat(menu): додати генерацію PDF-меню
fix(auth): виправити редирект після логіну
chore(deps): оновити next до 16.2.10
docs(readme): описати структуру папок
```

## Перед комітом

Husky автоматично запускає `lint-staged` (ESLint + Prettier) на застагованих файлах. Якщо хук падає — виправте помилки й спробуйте закомітити ще раз; не використовуйте `--no-verify`.

Перед відкриттям PR переконайтесь, що локально проходять:

```bash
npm run lint
npm run type-check
npm run build
```
